# 小型展示箱六路控制与图像识别扩展

用户已确认加入二氧化碳传感器、升降温执行器、成熟度识别和病害识别，规模为小型展示箱，仍以完成毕设为首要目标。本文件更新原四路版范围；原PDF及旧归档保留为历史版本，不代表新增功能已验收。

## 新增功能

| 功能 | 当前实现 | 仍需实物或样本证明 |
|---|---|---|
| CO2 | SCD41接口、ppm显示、上下限回差联动通风、CSV记录 | 实际读数、参照仪表对比、安装环境影响 |
| 升温 | 独立高电平输出，低于下限开启、回升1℃关闭 | 加热能力、表面温度、独立温控保护 |
| 降温 | 独立高电平输出，高于上限开启、回落1℃关闭 | 制冷能力、热端散热、冷凝水与实际停机 |
| 成熟度 | 本地视觉模型根据照片和用户填写的菌种输出阶段候选及可见依据 | 明确菌种、人工标注、分阶段独立验证集 |
| 病害识别 | 模型输出疑似异常、未见明显异常或无法判断及图像依据 | 健康与异常样本、专家标注、漏检与误报统计；不能确诊病原 |

六路输出为雾化、风机、清水泵、营养液泵、加热和制冷。视觉只读，不自动改变环境参数、不投药、不作食用判断。无法判读的图片保留“无法判断”，不填造置信度或准确率。

## 控制方法

先“启动系统”，再“启用温控与二氧化碳联动”。默认工程值为温度18/24℃、CO2为800/1200ppm，需结合最终菌种与导师意见另行确定。输入不是栽培处方。

- CO2达到上限时请求风机开启，降至下限取消请求；超限请求优先于手动关闭风机。全部停止仍关闭全部输出。
- 加热与制冷互斥，任一路停机或方向切换后至少间隔30秒，单次连续输出120秒后停止环境控制，检查后人工启动。开机也需等待30秒才可输出升降温。
- 温度到达5℃或40℃、CO2输入无效或超过15秒未更新，会停止已启用的温控联动及环境控制。原缺水、温湿度传感器和心跳失联保护继续有效。
- 温控联动未启用时，仍可进行原有湿度与通风演示，页面显示实际CO2状态；不能声称此时已自动调节CO2。
- 修改温控与CO2参数前先关闭联动；全部停止也会关闭联动，恢复后需重新启用。泵仍只在环境停止时运行。

可直接使用的中文指令：

1. 把温度下限设为18，上限设为24
2. 把二氧化碳下限设为800，上限设为1200
3. 启动系统
4. 启用温控与二氧化碳联动
5. 查询状态
6. 关闭温控与二氧化碳联动
7. 全部停止

每次单独发送并核对结果。旧固件没有climate状态字段时，后台拒绝新增命令，不能用虚拟CO2替代实测。

## 新增采购与接线

| 部件 | 数量 | 选型条件 |
|---|---:|---|
| SCD41模块 | 1 | 优先有厂家资料的成品模块，支持3.3V I2C逻辑；本版设计采用SCD41，不以空气质量指数或推算eCO2代替CO2读数 |
| 低压直流加热组件 | 1 | 12V成品PTC或加热组件，带独立温控保护、保险与防触碰结构，功率依据展示箱实测选择 |
| 低压制冷组件 | 1套 | 12V成品半导体制冷总成，含冷端、热端散热器及风扇；整个总成受控，不能直接给裸制冷片通电 |
| 负载驱动 | 新增2路 | 3.3V高电平有效、输入下拉默认关闭，容量按实际启动电流核对；不直接沿用小泵驱动额定值 |
| 独立保护与电源 | 按实际型号 | 热保护不依赖ESP32；电源、导线和保险按铭牌与同时工作负载匹配，散热失效应能切断热负载 |

GPIO16为加热输出，GPIO17为制冷输出，高电平启用；仅适用于这些引脚可用的经典ESP32-WROOM开发板，不能照搬到占用这些引脚的WROVER或其他板型。原GPIO与五个液位开关保持原分配。SCD41与AHT20共用GPIO21 SDA、22 SCL，地址分别0x62、0x38。

SCD41模块供电按模块手册安排，必须核对峰值电流与I2C上拉电压；不能仅看平均电流从开发板3V3随意取电。传感器和电路避开直接喷雾与冷凝；制冷热端置于箱外，确保热量排到箱外而不是重新加热箱体。低压设计不能省略热端保护、接水盘与冷凝隔离。

上传六个文件：main.py、controller.py、liquids.py、climate.py、aht20.py、scd4x.py。SCD41采用周期测量；每个数据字验证CRC，不就绪时等待而不伪造读数。驱动关闭本次上电的自动基线校准，不写入EEPROM；培养箱未必定期接触新鲜空气，校准需使用参照条件另行记录。

本方案没有确认具体加热/制冷商品和箱体热负荷，不承诺某个瓦数足够；先用匹配电源与仪表验证实际电流、散热和温度响应，再接入栽培环境。暂不控制空调或市电设备。

## 图像识别操作

本机Ollama固定端口11435，需已安装视觉模型qwen3-vl:2b-instruct。运行：

```powershell
.\run.ps1 -Mode demo -OllamaModel qwen3:4b -VisionModel qwen3-vl:2b-instruct
```

进入“成熟度与疑似病害识别”，拍照或导入本地PNG/JPEG，填写实际菌种，选择照片并分析。导入图片在浏览器缩放并转为1280×720以内PNG；显示识别照片编号，避免将上一次结果误当实时视频结论。智能体也支持“识别选定照片”，使用页面已经选择的照片及填写的菌种，不会自行开启摄像头。

每次成功结果保存于对应数据目录的vision子目录，JSON含照片编号与SHA256、时间、用户声明菌种、模型名称、预测类别和依据。记录标明尚未人工复核；页面可下载。完整备份会额外生成与SQLite备份同名的.vision.zip，两者需一起保留。记录是单次图像分析，不是持续自动视频诊断。

目前没有用户确认的菌种或标注样本，因此不能写识别准确率。应先选择一个菌种，将不同生长阶段和健康/疑似异常样本由导师或有经验人员标注；测试图片与调参图片分开，按培养批次分开，防止相似连拍图片造成虚高成绩。报告各类样本数、正确数、误报、漏检和无法判断数量，不能只展示几张成功图片。
