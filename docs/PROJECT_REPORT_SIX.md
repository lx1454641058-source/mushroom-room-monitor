# 蘑菇展示箱环境监测与智能体控制系统

项目介绍报告　六路控制与图像辅助识别版　2026年9月26日

## 一 项目概述

本项目以顺利完成毕业设计为首要约束，面向单个小型蘑菇展示箱，构建传感器采集、电脑显示、中文指令控制、异常停机和过程记录的一体化原型。用户可以通过网页或智能体查询温湿度与二氧化碳数据，设置控制参数，启动雾化、通风和升降温联动，限时抽水与释放营养液，并对保存的照片进行成熟阶段与疑似病害分析。

系统以ESP32作为采集控制板，以电脑承担数据存储和模型推理。六路输出分别为雾化、通风、清水泵、营养液泵、加热和制冷。当前控制软件、模拟与接口已通过88项自动测试及18项隔离启动流程检查；真实传感器、负载、水路和摄像头仍需联调，图像识别效果仍需针对具体菌种验证。本项目是毕业设计原型，尚不能据此声称具备工业无人值守能力。

## 二 功能与完成证据

| 模块 | 本版设计与实现 | 仍需取得的证据 |
|---|---|---|
| 环境采集 | AHT20温湿度、SCD41二氧化碳及五个液位输入，统一上报电脑 | 实际读数、参照仪表及安装记录 |
| 雾化与通风 | 湿度回差加湿、周期或限时通风；CO2超限请求优先通风 | 真实启停及环境响应曲线 |
| 升降温 | 独立加热/制冷输出，互斥、回差、停机间隔及连续时长保护 | 热负荷、散热和独立热保护测试 |
| 两路送液 | 清水1至30秒、营养液1至10秒，缺液/满液保护 | 实际时长、输送量与重复性 |
| 中文智能体 | 明确模板或本地模型解析，受限工具执行与结果反馈 | 指令、返回状态与实际动作对照 |
| 图像辅助识别 | 导入或拍照后分析成熟阶段与疑似异常，保存照片关联结果 | 菌种、人工标签、独立测试集 |
| 数据管理 | SQLite、CSV、统计报告、照片和识别JSON备份 | 导出可读、备份可核对 |

图像结果供人工复核，不自动改环境参数、不投药、不判断食用安全。营养液储罐需人工加液，本版不提供自动配方、每日自动投加或毫升定量控制。

## 三 系统架构

浏览器负责显示、相机和中文交互；Python后台负责状态检查、工具调度、USB串口及存储；ESP32负责读取传感器、计时控制与保护输出。摄像头直接连接电脑，图片不经过开发板。本机Ollama提供可选文字与视觉模型，模型权重不随源码包分发。模拟和实物数据分目录保存，界面明确标注来源。

## 四 展示箱硬件方案

建议先采用低压小型展示箱，最终尺寸与器件铭牌仍需确认。AHT20和SCD41共用I2C总线；原雾化、风机及两泵输出使用GPIO25、26、32、33，新增GPIO16和17分别控制加热与制冷。此分配仅适用于相关引脚可用的经典ESP32-WROOM板型。需要一起上传main.py、controller.py、liquids.py、climate.py、aht20.py、scd4x.py六个文件。

加热采用带独立温控保护的低压成品组件，制冷采用含冷热端、散热器及风扇的低压半导体制冷总成。热端放在箱外，电路避开喷雾与冷凝，电源和驱动按实际电流匹配。不能直接用GPIO带负载，也不能把裸制冷片当作完整制冷装置。具体功率要根据箱体和环境实测确定，本版暂不控制空调或市电设备。

清水水路为“清水罐 → 清水泵 → 雾化水箱”；营养液水路为“独立储罐 → 营养液泵 → 独立接收容器”。两套管路分开，营养液不进入雾化器。五个液位开关用于雾化低位、清水源低位、雾化高位、营养液源低位和接收容器高位。首次均使用清水试验，实际营养液用途和剂量需另行确认。

## 五 自动控制与保护

湿度采用上下限回差，默认65%RH启动、72%RH停止；雾化停机至少5秒，单次连续输出最多120秒。通风默认300秒一周期、开启15秒。温控联动需单独启用，默认低于或达到18℃加热，回升1℃停止；高于或达到24℃制冷，回落1℃停止。这些数值仅作工程演示，最终按菌种和生长阶段确认。

加热与制冷不能同时输出，停机或切换方向至少间隔30秒，任一路连续运行达到120秒后停止环境控制。CO2达到1200ppm请求通风，降至800ppm解除；该请求优先于手动关闭常规风机。“全部停止”仍会关闭全部输出。启用联动期间，CO2输入无效或15秒过期、温度达到5℃或40℃等异常会停机，恢复后需人工启动。

送液只能在环境控制停止时进行，两台泵互斥，运行中不允许重复启动来延长时长。源缺液、接收满液、输入过期、传感器或通信异常均按保护逻辑处理。后台每秒发送心跳，板端设计为最后有效心跳后10秒停机；实物延迟必须实测。页面断线后显示未知，不用旧状态宣称负载已断电，现场仍需独立断电手段。

## 六 智能体与视觉模型的分工

智能体将中文请求转换为允许的工具和参数，后台先检查整份计划，再调用控制接口；板端重复执行保护检查。模型不能直接操作GPIO、运行任意代码或修改保护规则。常用指令不依赖模型，例如“抽水5秒”“把温度下限设为18，上限设为24”“启用温控与二氧化碳联动”。人工停止会使尚未执行的旧计划失效。

视觉分析使用本地qwen3-vl:2b-instruct。用户选择已保存照片并填写真实菌种后，程序要求模型给出阶段候选、疑似异常及可见依据；模糊或无蘑菇时应返回无法判断。结果保存照片编号、SHA256、时间、模型与尚未人工复核标记。模型未配置、未下载、超时或结果结构错误时明确报错，不编造识别成功。实际模型联通记录见VALIDATION.md。

## 七 验证现状与实验方法

| 验证对象 | 已有软件证据 | 完整验收要求 |
|---|---|---|
| 控制与接口 | 88项测试、18项隔离HTTP检查，包含故障和旧固件边界 | 上板执行及六路真实负载记录 |
| 页面联动 | CO2优先通风、冷热切换、故障停机与恢复不重启已模拟操作 | 页面状态与负载实际动作一致 |
| 图像流程 | 图片导入、结果校验、照片关联、JSON备份测试 | 真实模型输出与人工标签比较 |
| 发布归档 | 文件散列、ZIP完整性与隔离运行验证 | 接收电脑按说明启动与复现 |

环境实验应同时记录传感器和参考仪表、环境条件、设定阈值、执行器实际启停与时间。分别验证加湿、升温、降温、通风和CO2响应，不能用模拟温度变化代替箱体热响应。升降温功率或换气能力不足时，应调整物理方案并重新测量，不用修改界面数值掩盖问题。

保护实验逐项记录触发、页面变化和实际负载停止时刻，覆盖缺水、源缺液、接收满液、传感器断开、通信中断、断电重启与热保护。两路泵先用清水各重复至少三次，保留时长与量杯读数；秒数不是毫升数。原始CSV、视频、照片与数据库备份需对应同一次实验。

识别实验先确认一个菌种，由导师或有经验人员给照片标注成熟阶段和可见异常。按栽培批次划分调试集和测试集，避免相似连拍图出现在两边。逐张保存人工标签、模型类别、是否无法判断和错误原因，报告各类样本数、混淆矩阵、误报、漏检与拒判数量。疑似病害不是病原确诊，未见明显异常不等于无病。
