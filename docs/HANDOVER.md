# 四路控制版使用与答辩演示说明

> 本文保留原四路演示流程。最新为小型展示箱六路方案，请先读 [EXTENSIONS.md](EXTENSIONS.md)。start-agent.cmd现配置文字模型qwen3:4b和视觉模型qwen3-vl:2b-instruct，需要本机Ollama的11435端口及对应模型已就绪；脚本不自动下载。新增演示顺序为：启动系统、启用温控与二氧化碳联动、演示CO2升高和温度场景、故障停机；照片分析需填写真实菌种，不能把模型结果当成领域准确率证明。

## 交接时先确认

这是毕业设计原型。软件模拟已验证，真实开发板、负载、水路和摄像头尚待验收。新版介绍见PROJECT_REPORT.md，开题稿见OPENING_REPORT.md，完整待办见DELIVERY.md。旧Word稿包含更大的拟建范围，不作为当前功能清单。

解压源码ZIP到新目录。不要覆盖旧项目或数据库。模拟仅需Python 3.10或更新版本，双击start-demo.cmd，保留启动窗口，打开http://127.0.0.1:8770。端口被占用时运行`.\run.ps1 -Mode demo -Port 8771`；停止在启动窗口按Ctrl+C。

首次运行点击“恢复场景”，核对“模拟演示”标记与四路输出关闭。模拟数值不能写成论文实测。智能体每条消息写清对象、动作与数字；常用示例无需模型。其他自然语言表达需要事先运行本地Ollama及模型，再使用start-agent.cmd，不会自动安装或下载。

## 八分钟答辩演示

| 时间 | 操作 | 应说明的要点 |
|---|---|---|
| 0至1分钟 | 展示总体页面与“查询状态” | 单箱、四路输出、温度仅监测；明确当前数据来源 |
| 1至2分钟 | 模拟“湿度降低”，发送“把湿度下限设为65，上限设为75，然后启动系统” | 参数校验后执行，湿度回差与最短停机间隔 |
| 2至3分钟 | 模拟“湿度升高”，再“通风30秒” | 加湿关闭，风机限时后恢复周期；数值仅作演示 |
| 3至4分钟 | 模拟缺水，再尝试启动 | 拒绝启动有理由；恢复后需人工重启 |
| 4至5分钟 | 恢复场景并全部停止，发送“抽水5秒” | 环境控制与泵互斥，水源和接收液位满足才运行 |
| 5至6分钟 | 再次恢复场景，发送“释放营养液3秒”，观察到时停止 | 独立水路、单次限时，不声称送出了固定毫升数 |
| 6至7分钟 | 展示摄像头照片及CSV、统计报告 | 摄像头需本人允许访问；未实测时展示待验收项 |
| 7至8分钟 | “全部停止”，展示执行记录与验收表 | 模型负责解析，程序执行保护；说明实物完成程度 |

演示两台泵时不要在其中一台仍运行时启动另一台。重复同一泵需等待停止后至少5秒。“恢复场景”只用于模拟，实物模式需真实改变并检查条件。结束后核对四路关闭。

## 接实物的顺序

1. 按PROCUREMENT.md逐项确认开发板、风机、泵、雾化器、驱动、电源及五个液位开关。不要按商品外观猜电压或端子。
2. 保留板上旧程序，确认后将main.py、controller.py、liquids.py、aht20.py放入匹配的MicroPython板载文件系统根目录。具体刷写版本与工具需随板型确认。
3. 按HARDWARE.md先做无负载试验，再逐路接入低压负载。实测默认关闭、浮球方向与各保护动作。泵先用清水接量杯。
4. 在项目目录执行`python -m pip install --target .runtime -r requirements-hardware.txt`安装串口依赖；COM5仅作示例，实际使用`.\run.ps1 -Mode serial -SerialPort COM5`。
5. 确保没有其他编辑器占用串口。页面应标为实物模式；故障不自动回退假数据，不自动重连启动。掉线后先检查现场，再重启后台。
6. 完成ACCEPTANCE.md，保存每个试验的CSV、视频、照片和配置。真实摄像头需本人允许访问，并实际等待下一次定时照片。

## 数据交接

模拟在`.data/demo`，实物在`.data/serial`。CSV最近最多10万条，统计报告最近最多3600条；不能把导出上限当作完整历史。页面“备份数据”或备份脚本保存完整数据库，包括照片和事件。

需要查看备份时复制到新建目录，按README.md检查副本，保留原始数据。源码ZIP不含本机数据库、照片、解释器或模型，证据文件另存；不要公开包含私人画面的照片。

## 常见现象

| 现象 | 先检查 |
|---|---|
| 不出雾 | 查询“为什么不出雾”，检查启用状态、液位、传感器、湿度阈值、停机间隔和真实负载 |
| 泵被拒绝 | 环境是否停止、另一泵是否运行、源是否缺液、接收是否满液、是否在5秒间隔内 |
| 模型错误或超时 | 改用明确模板或按钮，核对本机11435端口模型服务；不要重复发送不确定的泵指令 |
| 显示设备未知 | 查看USB、串口占用和固件；未知不等于负载已经停机 |
| 无照片 | 开启摄像头并由本人授权，先手动保存验证；定时需页面打开、电脑唤醒 |
| 接收液体仍在流动 | 现场断电并检查虹吸、管路固定与余液，不能仅靠页面停止状态判断 |

## 答辩表述

可以说：“本系统用ESP32采集温湿度与液位，电脑端智能体将明确中文指令转换为受限工具调用，底层程序完成雾化、通风、限时送液和异常保护。系统记录执行结果，模拟与实物数据分开保存。”

不要说“AI自主判断最佳栽培参数”“视觉自动识别长势”“定时泵实现精确毫升投加”或“已经实现工业无人值守”，这些均没有对应的实现或验收证据。论文贡献可以围绕受限指令执行、上下位机保护分工、异常状态处理和可追溯验证展开。
