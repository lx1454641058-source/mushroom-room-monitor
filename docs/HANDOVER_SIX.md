# 六路展示箱交接与答辩演示

当前可以运行软件模拟。真实开发板、负载、摄像头和图像识别效果尚需验收；本文件与PROJECT_REPORT_SIX.md、OPENING_REPORT_SIX.md为最新六路材料，旧四路PDF保留为历史版本。

## 启动与停止

1. 将交付包解压到新目录，保留旧工程与原始数据。安装Python 3.10或更新版本后，在mushroom-room内双击start-demo.cmd。
2. 保留启动窗口，访问 http://127.0.0.1:8770 。端口冲突时使用 `.\run.ps1 -Mode demo -Port 8771`。
3. 本机Ollama已在11435端口运行且两个模型已安装时，可用start-agent.cmd启用qwen3:4b文字模型和qwen3-vl:2b-instruct视觉模型。脚本不自动安装或下载；模型失败时页面明确报错。
4. 结束前点击全部停止并核对状态，然后在启动窗口按Ctrl+C。网页关闭不等于后台停止，关闭网页会停止页面内定时拍照。

## 约十分钟的软件演示

| 顺序 | 操作 | 讲解与证据 |
|---|---|---|
| 1 | 恢复场景，查询状态 | 明确当前是模拟，六路默认关闭 |
| 2 | 设置湿度并启动环境 | 回差控制，数据与执行状态分开 |
| 3 | 发送“启用温控与二氧化碳联动” | 独立启用，工程默认温度18/24℃、CO2 800/1200ppm |
| 4 | CO2升高，再手动关闭常规通风 | 超限请求优先，全部停止仍有效 |
| 5 | 温度降低，再温度升高 | 加热/制冷互斥，停后30秒才可再次输出 |
| 6 | CO2传感器故障，再恢复场景 | 故障停止，恢复不自动重启 |
| 7 | 抽水5秒，等待停止；再营养液3秒 | 两泵与环境互斥，时长不是体积 |
| 8 | 选已保存照片，填真实菌种，识别选定照片 | 检查照片编号、模型结果、无法判断及人工复核标记 |
| 9 | 导出CSV、生成报告、备份数据 | 模拟不当作实测，SQLite与.vision.zip一起留存 |
| 10 | 全部停止，说明待完成项目 | 真实硬件、参考仪表和识别测试集待验收 |

模型尚未就绪时第8步应展示未完成提示，不能把预填结果冒充实际推理。空白测试图片不是蘑菇样本。真实摄像头需用户授权后才能开始，不能以电脑检测到相机代替成像验证。

## 实物接入前置条件

确认开发板完整型号和现有程序保留需求，再按HARDWARE.md、PROCUREMENT.md与EXTENSIONS.md核对供电、驱动、引脚、五个液位触点、散热和热保护。新版必须同时部署六个固件文件；旧固件仍可读基础状态，但后台会拒绝其不具备的新功能。

先不接负载验证六路默认关闭，再逐路在看护下接入。全部用清水试水并检查虹吸、泄漏和接收余量。真实串口模式示例为 `.\run.ps1 -Mode serial -SerialPort COMx`，COMx必须替换为已确认开发板端口，不试探蓝牙或无关串口。

## 数据与材料交接

- 原始数据分别位于.data/demo与.data/serial，严禁把模拟库改名成实物库。
- 完整备份包含SQLite及存在识别记录时的同名.vision.zip；单独CSV不包含照片与识别JSON。
- 照片识别记录保存照片SHA256、用户填写菌种、模型、时间与预测，人工标签应另表保存，不改写原模型输出。
- RELEASE.json记录本次源码的88项软件测试、18项接口检查及SHA256；HANDOVER-MANIFEST.json用于组合包文件核对。文件一致不证明完成实物实验。
- 最新介绍与开题稿可编辑源在docs，PDF在交付包reports目录。姓名与学校信息留空；不预填实测结果。

下一阶段按ACCEPTANCE.md和EXTENSIONS.md记录真实实验，并补充图像评估。最终论文、答辩结论和准确率必须来自这些记录。
