# 蘑菇房环境监测与智能体控制系统

> 历史四路版报告。本次用户确认小型展示箱并追加CO2、加热、制冷和图像识别，最新设计与实施状态见 [EXTENSIONS.md](EXTENSIONS.md)。下文的未实现项目和74项测试数对应旧版，不能作为当前范围；新增功能也不能视为已经通过实物或图像准确率验收。

项目介绍报告　四路控制版　2026年9月26日

## 项目概述

本项目面向毕业设计，设计一套小型蘑菇展示箱监测与控制原型。系统由ESP32开发板、温湿度传感器、液位开关、四路执行器、电脑后台和摄像头组成，实现环境采集、状态显示、中文指令控制、异常停机以及数据与照片留存。用户可以通过智能体查询环境、设置湿度阈值、启动加湿通风、限时抽水和释放营养液，并查看执行结果。

项目以易搭建、易解释和易验收为原则。当前软件模拟、接口与控制逻辑已通过74项自动测试，并完成独立目录启动检查；开发板、真实负载、水路和摄像头尚待实物验收。本报告介绍已实现的软件及配套硬件设计，不将模拟结果视为实际栽培实验，也不承诺工业无人值守能力。

## 需求与功能范围

| 模块 | 本版功能 | 验收时观察的证据 |
|---|---|---|
| 环境监测 | AHT20采集温度与湿度，液位开关提供允许状态 | 实时读数、原始CSV、参考仪表记录 |
| 雾化与通风 | 湿度上下限控制雾化；周期通风或手动通风30秒 | 指令记录与真实负载启停视频 |
| 清水补给 | 清水储罐向雾化水箱单次输送1至30整数秒 | 实际运行时长、液位保护与量杯读数 |
| 营养液释放 | 独立储罐向接收容器单次输送1至10整数秒 | 到时停止、缺液与满液保护记录 |
| 视觉观察 | 摄像头预览、拍照保存、页面打开时每5分钟拍照 | 实际照片和保存时间 |
| 智能体 | 中文查询、参数设置和受限工具执行 | 执行步骤、参数变化和操作日志 |
| 数据管理 | 本机SQLite存储、CSV导出、统计报告与完整备份 | 导出文件与备份完整性检查 |

温度仅监测，摄像头仅用于人工观察与记录。系统没有接入二氧化碳传感器、升降温执行器、成熟度识别、病害识别或自动营养配方。储罐需人工加液，泵控制采用单次限时方式，不提供每天自动投加或毫升定量。

## 系统组成

电脑浏览器承担界面、摄像头和中文交互；Python后台承担状态管理、指令校验、USB串口通信与存储；ESP32承担传感器读取、计时控制和输出保护。摄像头直接连接电脑，不经过ESP32。模拟与实物使用相同的控制逻辑，但数据分别保存，页面明确标注来源。

## 硬件与水路设计

工程演示建议使用约40至60升透明箱，配置一台12V直流排风扇、配套低压雾化组件、两台12V蠕动泵和五个浮球液位开关。蠕动泵通过挤压软管输送液体，电机与管内液体分离。现有空调不纳入本版控制；最终风机、驱动和电源按实际型号核对后采购。

清水水路为“清水储罐 → 清水泵 → 雾化水箱”。清水罐检测缺液，雾化水箱同时检测缺水与满水。营养液水路为“营养液储罐 → 营养液泵 → 独立接收容器”，源罐检测缺液，接收容器检测满液。两套管路分开，不将营养液送入雾化器。首次全部用清水调试，实际营养液用途、配方及投加量须另外确认。

经典ESP32使用GPIO25、26、32、33分别控制雾化、风机、清水泵和营养液泵，GPIO21与22连接AHT20。负载由匹配电源通过驱动模块供电，不能直接接GPIO。液位开关闭合至GND才表示允许，断线按不允许处理。完整接线、触点方向和采购条件见配套PROCUREMENT.md与HARDWARE.md。

## 自动控制与保护

加湿采用上下限回差：湿度达到或低于下限时开启，达到或超过上限时关闭，在两阈值之间保持先前状态，以减少频繁切换。默认65%RH与72%RH、通风300秒一周期且开启15秒，仅用于工程演示，不代表任何菌种的栽培处方。雾化最短停机间隔为5秒，单次连续加湿达到120秒时停机，检查后人工重启。

泵必须在环境控制停止后使用，且两台泵不能同时运行。单次时长受限，运行中不能通过重复启动延长时间；同一泵停止后至少等待5秒。源罐缺液、接收满液、液位输入过期、环境传感器无效或心跳失联均撤销输送。保护条件恢复不会自动重新运行。

后台通过心跳让开发板确认通信仍在维持。固件按最后一次有效心跳后10秒停机设计；真实响应时间需上板测量。断线页面将输出显示为未知，不能用旧状态判断设备是否已停止。“全部停止”用于关闭四路输出，但仍依赖通信，实物应保留独立手动断电手段。

## 智能体如何控制设备

中文指令先由明确模板或可选本地语言模型解析，再转换为允许的工具和参数。后台检查整份计划、数值范围与当前状态，之后调用控制接口；板端再执行计时和保护，并返回结果。语言模型不能直接访问GPIO、执行任意代码或绕过保护。常用模板不依赖模型；启用模型时复用本机Ollama与qwen3:4b。

例如“把湿度下限设为65，上限设为75，然后启动系统”依次修改参数和启动；“抽水5秒”调用清水泵限时工具。参数不合法、指令含糊或设备条件不满足时拒绝执行。每条消息独立理解，不根据“继续”“再来一次”等省略句猜测动作。模型规划期间若发生人工停止或状态切换，旧控制计划失效。

## 实物实验安排

首先核对开发板、负载、驱动、电源和浮球触点方向，在不接负载时验证四路默认关闭。随后逐路接入负载，分别记录雾化、通风和两台泵的实际动作。对清水和营养液两路用清水计时、量杯测量并至少重复三次，保留每次读数；运行秒数不能直接当作毫升数。

环境实验保存传感器与参考温湿度计读数，记录加湿前、加湿中和达到上限后的曲线。保护实验分别记录触发、页面变化及负载实际停止时刻，包括缺水、缺液、满液、传感器断开和通信中断。照片至少保留两个实际时间点，并验证定时拍照在页面保持打开时工作。数据与照片完成后生成报告、导出CSV并备份数据库。

交付内容包括电脑后台、网页、ESP32四个固件文件、自动测试、采购接线文档、智能体说明、验收表和本报告。源码包不含解释器、模型、用户数据库或照片。默认模拟模式仅需Python 3.10或更新版本；实物模式增加pySerial，模型为可选项。
